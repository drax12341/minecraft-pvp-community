# CommunityArena 6.0.0 preview

Paper **1.21.11**, Java **21+**. This is one server plugin JAR. No client mod, external AI gateway, or extra runtime plugin is required.

Stop the server, back up all worlds and `plugins/CommunityArena/` together, replace the previous CommunityArena JAR with `CommunityArena-6.0.0.jar`, and restart. Keep the data folder and terrain journals. Do not install two versions or use `/reload`.

## Maps that generate without the old construction wait

New owned worlds are **community_arena_v6** and **community_citadel_v6**. The old v4 arena/citadel and v3 grove are preserved for recovery and rollback. Existing built-in lobby selections move to the new courtyard; an external/custom lobby stays selected. `/pvpadmin usecitadel` selects the new courtyard explicitly.

Eighteen arenas remain: Meadow, Dunes, Jungle, Alpine, Cherry and Badlands, each in 50x50, 150x250 and 250x350 sizes, with ceilings Y=110/180/280. Sword, Axe and UHC use Compact maps. Native chunk generation builds bedrock floors, invisible boundary shells, level spawn lanes, surrounding ridges, worn gateways, terrain palettes and biome-specific scenery. The jungle has taller, denser trees; meadow/cherry have gentler footing; dunes and badlands include small ruined arches. The new courtyard has four roofed pavilions, planted arcades, lanterns and a central fountain. Legacy queue/FFA sectors are also generated by the new generator.

The JAR contains deterministic build code, not external world downloads. Maps generate as native chunks load. A background prewarm visits **3,168 chunks**, one asynchronous request at a time, with Compact arenas first. It pauses while any duel, bot, party battle or FFA session is active and requests completed chunks to unload. `/pvpadmin maps` reports progress/errors; wait for **`Map prewarm finished ... failures=0`** before opening publicly if you want the whole catalogue generated ahead of play. Initial generation consumes CPU/IO and can take several minutes. `maps.prewarm: false` disables the background pass; normal native generation still works.

The six-theme overview in the release is rendered from the actual terrain planner using flat material colours. It is a structural preview, not a native Minecraft screenshot or a texture/shader promise. The complete native chunk pipeline and client visuals still need live staging verification.

## Nine normal presets

The normal set is **Sword, Axe, UHC, Diamond Pot, Netherite Pot, SMP, Crystal, Mace and Spear Mace**. Bow, Boxing, Diamond SMP and the separate Breach/Density modes are removed from public selection/queues. Historical data is preserved; no old ratings are fabricated or converted. Existing player-created saved custom kits remain separate.

The supplied screenshots are the authority for visible item types, stacks and inventory positions. In particular: Axe has sword/axe/bow/crossbow and five arrows; Diamond Pot has healing potions and five offhand steaks, without invented pearls; Netherite Pot has offhand apples, two totems and XP; UHC has two golden heads, eight apples, eight webs and the pictured bucket reserves; Crystal has the pictured pearl/totem rows, crossbow, tipped arrows and shield; Mace has both maces, elytra, wind charges, shield and spare shulker; Spear Mace includes a real native netherite spear **and a mace**, with rockets and elytra.

**Inferred details, approved by the owner:** screenshots do not expose enchantments, potion effects/durations, skull/banner textures, elytra durability, loaded crossbow ammunition or shulker contents. These are not claimed to be an official MCTiers export:

- Sword uses Sharpness V and diamond Protection III. Other enchanted presets use Sharpness V/Protection IV; UHC sword/axe use Sharpness III. Axe equipment is unenchanted. Enchanted armor uses Unbreaking III/Mending and Feather Falling IV on boots; Crystal leggings use Blast Protection IV.
- Utility potion colours are interpreted as Strength II, Swiftness II and long Fire Resistance. Healing uses Instant Health II; these are splash potions as pictured. No strength, speed or fire-resistance effect is silently applied before drinking/throwing a potion. The small Spear Mace image's indistinct potion metadata is inferred.
- Regular Mace has Breach IV and Density V maces; the Density mace and Spear Mace's mace use Wind Burst III. Weapons use Unbreaking III; inferred maces/spear also use Mending. Elytra uses its default durability with Unbreaking III; the regular Mace elytra also has Mending.

Old `kits.*` operator overrides and old positional layouts cannot replace the new reference presets. New operator overrides use `kits-v6.*` and new layouts use `players.<uuid>.layouts-v6.*`. Old values remain in the data file for rollback. `/pvpadmin kit <kit>` still allows an intentional new operator override; use it for authoritative kit exports if supplied later.

## Lobby layout editor

Right-click the **anvil in lobby hotbar slot 6** (inventory index 5), use Navigation → Kit Layout Editor, or type `/layout`. Choose one of the nine presets in the three-by-three picker. `/layout <kit>` still works. The editor shows storage/hotbar plus locked armor/offhand previews. It reopens your saved arrangement, swaps complete stacks, and preserves item counts and metadata. Opening it no longer temporarily equips or teleports the player. Original pre-practice inventory backups are unchanged.

All previous private duel settings, parties, friends-tab toggling and operator bot practice remain. See INSTALL-V5.md for those commands. Private/bot/party sessions never award community HT/LT placements; bot/party sessions do not award Elo or statistics.

## Performance, safety and limits

The old all-map main-thread builder is removed. New terrain uses native ChunkData generation; it does not call live-world block APIs, create entities or write files from a generator worker. The map catalogue is immutable and reused, and map lookup uses the arena grid directly. Nameplate visibility and menu-border mutations update only on changes. Kit previews read equipment directly.

New v6 arena entities are temporary/nonpersistent. Spawn/projectile hooks and entity-unload cleanup prevent TNT, arrows, dropped loot and bots from surviving reuse. Reset scans loaded chunks only in the fresh v6 world. **Legacy v4/v3 recovery still scans its original bounded chunks**, restores journals in the original world, and fails closed when a required world is missing. Journal prefixes are separate; synchronous write-ahead durability and recovery reservations are retained. World saves and journal IO can still pause on slow storage.

The operation-count fixtures measure avoided work, **not real TPS or packet-rate improvements**: 24 viewers over 20 stable visibility refreshes go from 480 visibility API calls to zero; unchanged scene state is still retained. A Sky map's old reset scanned 352 chunks; the new reset does not force additional unloaded chunks into memory. The old eighteen-map builder required at least 12,240,000 main-thread floor/ceiling block writes; that scheduled builder no longer exists. Background generation still has a cost.

No ping value is spoofed. Network RTT depends on host location, routing, congestion and the client's connection. For a live baseline, use Paper's bundled spark: `/spark profiler start --timeout 120` during the same player count/activity before and after upgrading, and compare server tick times and the profile. See [Paper profiling documentation](https://docs.papermc.io/paper/profiling/). This plugin does not edit global server properties or other plugins' configurations.

Build: `mvn -f arena/pom.xml clean verify`. Automated coverage includes nine-preset slot/count checks, editor safety, head use, native spear/mace presence, all-map spawn/floor/boundary checks, deterministic worker-safe terrain, native biome selection, full warmup coverage/failures/concurrency/pause, entity unload cleanup, old-world fail-closed recovery and the existing duel suite. Test fixtures model height and unavailable native transports explicitly; they are not a native Paper restart or load test.

**Unverified:** actual Minecraft client appearance, live native chunk/entity IO across power loss, regional ping, native moving-bot feel and fifty-player TPS. Stage this preview before public use. Roll back using the prior JAR plus the matching full world/data backup; do not delete recovery journals.

The five requested skills were applied: Ponytail for focused reuse, Graphify for targeted call/relationship tracing without an existing graph, security hardening for session/permission/recovery boundaries, and independent code review. OmniRoute remains unrelated to native Minecraft gameplay. Discord files and GitHub Pages hosting are unchanged by this upgrade.
